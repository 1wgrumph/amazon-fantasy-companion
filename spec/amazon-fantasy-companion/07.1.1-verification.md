#### 7.1.1 Profile and access

Profile verification separates retained customer choices from detected facts and verified access. This protects the viewer from a refreshed detector result silently changing their selections or being mistaken for a subscription; the cases below combine backend checks with restart and override demonstrations on the stick.

Table (T1): Profile and access verification approach

| UID / case | Allocated element(s) | Method, environment and acceptance evidence |
|---|---|---|
| AFC-PR-001 / VCASE-AFC-PR-001 | LINEUP | Test, backend, AWS Free-plan deployment (SD-005). Positive: roster distinguishes active slots from bench and returns scoring settings. Negative: no write-scope call is attempted and no player eligibility value is used as a starting-slot fact. VCASE-AFC-PR-001. |
| AFC-PR-002 / VCASE-AFC-PR-002 | PROFILE, API, STORE | Demonstration, system, real stick (SD-001) + backend. Positive: select, restart, selections retained. Negative: no selection silently dropped. VCASE-AFC-PR-002. |
| AFC-PR-003 / VCASE-AFC-PR-003 | DETECTOR | Demonstration, tv-app, real stick (SD-001). Positive: each installed supported app reported installed. Negative: absent app never reported installed. VCASE-AFC-PR-003. |
| AFC-PR-004 / VCASE-AFC-PR-004 | RESOLVER, API | Test, backend, AWS deployment. Positive: verified marking carries basis integration or confirmation. Negative: installed-app fact alone never yields verified. VCASE-AFC-PR-004. |
| AFC-PR-005 / VCASE-AFC-PR-005 | PROFILE, STORE | Demonstration, tv-app, real stick (SD-001). Positive: override of a detected app and of local market persists across restart and feed refresh. Negative: refresh never silently discards an override. VCASE-AFC-PR-005. |
