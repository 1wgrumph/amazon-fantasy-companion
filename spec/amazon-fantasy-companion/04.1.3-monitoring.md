#### 4.1.3 Monitoring and viewing context

**BLUF:** Monitoring uses enabled periods and labels the evidence behind every decision.

**Frame**

- **Who:** Product implementation and verification teams.
- **What:** Monitoring and viewing context.
- **Why:** Preserve the approved experience and its evidence boundaries.
- **How:** Apply the cited register and model contracts.
- **When:** Phase 2 implementation and subsequent verification.
- **Where:** Fire TV companion and AWS backend.

`backend.ingest` monitors the relevant game set selected by `backend.policy`; quiet hours and game-day settings bound this set. The profile carries the schedule/game-day mode explicitly. Supported, opted-in viewing observations can refine context; otherwise decisions carry `profile-assumption`, never `observed-playback`.

Master detection/personalization opt-out disables use of detection data and profile-based personalization. It does not authorize silently resuming detection when settings refresh. Schedule-driven monitoring remains possible as specified by the register, with its basis labeled; observed context cannot be reconstructed from an assumption. The exact OS mechanism is a spike output.
