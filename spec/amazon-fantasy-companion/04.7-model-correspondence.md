### 4.7 Model correspondence

**BLUF:** Text and diagrams preserve the native model’s scope and explicitly identify refinements.

**Frame**

- **Who:** Product implementation and verification teams.
- **What:** Model correspondence.
- **Why:** Preserve the approved experience and its evidence boundaries.
- **How:** Apply the cited register and model contracts.
- **When:** Phase 2 implementation and subsequent verification.
- **Where:** Fire TV companion and AWS backend.

The four packages are self-contained; cross-package linkage is by documented element names and the allocation companion, not formal imported flow bindings. `AFCData` imports `ScalarValues` for its primitive types. The ST-3d receipt closes the earlier parser-unavailable gap; it does not validate wire contracts or real-device behavior.

AlertLifecycle follows detected → matched → gated → emitted → delivered, with matched → suppressed and emitted/delivered → corrected. PanelMode starts in modeB and transitions only to modeA on spikeFailed. DeviceLink starts unlinked, requests codePending, then links on userConfirm or expires on codeTimeout; expired can request again. Sections 4.1.5, 4.1.10 and 4.1.12 draw these separately.

Identity/revision envelopes, JSON typing, authorization/error handling and API operation signatures are D1 refinements of the named interfaces. They do not amend native models or claim model conformance beyond the recorded parse. Model omissions such as cancellation, account unlink/revocation lifecycle and transport tuning remain Phase 2 contract work, not silently completed state transitions.
