#### 4.1.4 Event ingest and replay

**BLUF:** Validation precedes any mutation of stored game events.

**Frame**

- **Who:** Product implementation and verification teams.
- **What:** Event ingest and replay.
- **Why:** Preserve the approved experience and its evidence boundaries.
- **How:** Apply the cited register and model contracts.
- **When:** Phase 2 implementation and subsequent verification.
- **Where:** Fire TV companion and AWS backend.

`backend.ingest` treats ESPN unofficial JSON as untrusted input and normalizes the event contract only after complete response validation. A rejected response leaves stored events unchanged. Endpoint outage or a changed contract selects `backend.replay` and `stores.fixtures` for affected values with source labeling propagated to alerts and panel data.

Replay is a data-source substitution, while Mode A is a video-composition fallback; either can occur independently. Source timestamps and correction references survive normalization. A transport retry cannot turn malformed or old content into fresh live facts.
