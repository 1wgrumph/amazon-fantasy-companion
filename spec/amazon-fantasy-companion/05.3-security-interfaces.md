### 5.3 Security interfaces

**BLUF:** API and provider boundaries preserve access evidence and avoid secret transfer.

**Frame**

- **Who:** Product implementation and verification teams.
- **What:** Security interfaces.
- **Why:** Preserve the approved experience and its evidence boundaries.
- **How:** Apply the cited register and model contracts.
- **When:** Phase 2 implementation and subsequent verification.
- **Where:** Fire TV companion and AWS backend.

Use TLS for TV/backend and external service calls; authorize every profile-scoped operation. Store OAuth material only in SSM SecureString and scope runtime access to the needed parameters. TV-facing results carry access status and basis rather than raw subscription credentials. Installation facts alone cannot produce verified inclusion.

A URI handler or successful intent dispatch is not an entitlement check. Keep safe diagnostic identifiers and explicit route outcomes while excluding tokens and raw customer data from logs/screenshots. Open security contract items in 4.2.3 are prerequisites to implementing the public-facing path; D1 does not certify them as realized.
