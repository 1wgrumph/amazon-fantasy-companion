BUG-A02-1 implementation verification, 2026-10-20 (author self-check)
Device: Fire TV AFTKM, Fire OS 8.1.8.5, Android API 30, 1920x1080.
Scope: ProfileSettingsScreen shared text-field helper; its instrumented regression; changelog and this evidence. Synthetic form data only.

Origin and missed detection
- Confirmed 2ca71d6 introduced the profile text editors and 2bc65cc expanded them. The baseline has five BasicTextField sites with no vertical D-pad or explicit IME-action handling.
- The baseline androidTest tree contains only AlertNotifierDeviceTest. ProfileControls JVM tests check logic, not actual remote traversal through an editable field.
- On Fire TV the software keyboard consumes the vertical key before an ordinary onPreviewKeyEvent handler receives it. preview-handler-failed.txt demonstrates that the unfinished handler still fails at Team focus.
- This is a product focus defect; signer mismatch, sleeping device and missing UTP artifacts are separate harness/environment conditions, not product red evidence.

Fix
- ProfileTextField is reused for name-list drafts, league, team, app-override draft and market. Navigation focuses a read-only field with a visible border; Select/Enter or the accessibility click action starts editing. While editing, the Amazon keyboard retains its vertical letter-grid navigation. Back returns to form navigation; outside editing, vertical KeyDown events move focus Up/Down before the IME can consume them.
- IME Next ends editing, hides the keyboard and follows forward focus order; Done ends editing and delegates to Compose's standard keyboard-dismiss action. The pinned Compose 1.7.6 API requires a narrowly scoped ExperimentalComposeUiApi opt-in.
- Draft callbacks and Set/Clear/Save implementations are unchanged. An unconditional pre-keyboard interceptor was rejected because it would also intercept movement through the keyboard grid. Navigation/editing state preserves both uses of the remote.
