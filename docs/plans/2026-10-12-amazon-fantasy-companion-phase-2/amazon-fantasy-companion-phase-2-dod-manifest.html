3Outcome, scope, exclusions, and Definition of Done

Planned outcome

Phase 2 builds and submits the product the approved specification describes (`spec/amazon-fantasy-companion/amazon-fantasy-companion.md`, owner approval DEC-AFC-APPROVAL-ST5). When it is done: - **A Fire TV app** (Kotlin/Gradle, from the starter `AmazonAppDev/hello-world-fire-tv`, minSdk 25) runs on the owner's 2018 stick on Fire OS (SD-001, SD-003). It links to the backend by device code, holds the customer's profile and every customer control, shows a heads-up alert with Watch and Dismiss over a provider app's playback, opens the resolved provider game or channel and reports the routing outcome, and shows the right-side lineup panel beside provider video, or the full-screen panel when the spike shows that route does not exist (AFC-PR-047, DEC-AFC-SD-035). - **An AWS serverless backend** on the owner's new Free-plan account (SD-005, C4) ingests ESPN's unofficial public JSON (SD-004) with labeled replay (C2), reads the lineup from Yahoo or labeled manual entry after T_yahoo (C6) with the PPR / Half-PPR presets (AFC-PR-065), matches identities, applies the alert policy (close game within 8 points in the 4th quarter or overtime, stale after 60 s, excitement Off / Mild / Hype), resolves the provider and channel and serves the panel. - **Spikes run first and are time-boxed.** Each writes a verdict that records exactly which routes work on the real stick (issue #1 §Development integration obligation). Their verdicts select the panel mode, the provider link contracts and the notification route before product code depends on them. - **The submission is ready before T_deadline:** README and setup instructions, judge access through T_judge_access, a demo video plan under three minutes, a write-up (with the YouTube TV Fantasy View differentiation and the DEC-AFC-SD-036 future direction, cited, discussion only), and the developer feedback assembled from the Scribe log (DEC-AFC-SD-025). The owner submits. - **Every landed slice is visible in the revision record** (DEC-AFC-SD-038): a `CHANGELOG.md` `[Unreleased]` entry linking its pull request, and one release per milestone prepared through the `release-process` skill. The owner authorizes each publication. - **GitHub milestones M1..M5** (D3) are defined here and created only after this package is approved (P2-7). Every slice traces register UIDs (`requirements-register.md`) and spec sections. Phase 2 adds no product requirement; Lifecycle-local criteria below cover write sets, seams, gates, schedule, submission and the revision record only.
